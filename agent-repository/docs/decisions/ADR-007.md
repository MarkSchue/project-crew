# ADR-007: Use policy-enforced tools rather than relying on prompt restrictions

- **Decision owner:** project_architect
- **Decision date:** 2026-08-24
- **Status:** accepted
- **Scope:** Enforcement point for file access, network access, and
  prohibited actions.

## Options considered

1. Tool-side enforcement: every tool call is authorized against the
   compiled manifest's allowlists and the policy engine before it executes,
   independent of what the prompt says (selected, masterplan section 3.6,
   15.5).
2. Prompt-only restrictions (instructing the agent not to access certain
   paths/actions).
3. Sandboxed process isolation only, with no explicit per-call
   authorization.

## Decision drivers

- Prompt injection is an identified threat (masterplan section 15.4-15.5,
  section 25 risk table).
- "Policies override prompts" is a stated architectural principle
  (masterplan principle 8).
- Directory conventions alone do not protect private data (masterplan
  section 3.6).

## Selected option

File tools resolve canonical paths, reject symlink escapes, and enforce
manifest-derived read/write allowlists; all tool calls pass through a
`PolicyDecisionPoint` before executing, fail-closed on policy engine
error (masterplan section 15, plan section 20.1).

## Rejected options and reason

- Option 2: an LLM can be manipulated via prompt injection into ignoring
  instructions; this is not a security boundary.
- Option 3: process isolation alone does not express fine-grained,
  per-manifest allowlists (which paths, which classifications).

## Security and compliance impact

This is the primary technical control against prompt-injection-driven
unauthorized actions (masterplan section 15.4-15.5) and against
cross-project data access.

## Operational impact

Every tool must declare a contract in the tool registry (masterplan
section 14.1) and be independently testable against denial cases (path
traversal, symlink escape, classification breach — plan section 18.7
security test layer).

## Cost impact category

None additional.

## Portability impact

None additional — the policy decision point is an application port (plan
section 20.1); the concrete policy engine technology is decided in
ADR-016.

## Revisit trigger

None anticipated; this is a foundational security control.

None.

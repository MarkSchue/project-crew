# ADR-012: Checkpoint authority

- **Decision owner:** project_architect
- **Decision date:** 2026-08-24
- **Status:** accepted
- **Scope:** Which system is authoritative for run/attempt checkpoints, and
  how application state, Flow state, and database state map to it.

## Options considered

1. A single `RunStateStore` port is the sole checkpoint authority; CrewAI
   Flow's own persistence, if used, is one possible adapter implementation
   behind that port, never a second independent write path (selected,
   plan section 17.1 second correction).
2. Two independent checkpoints: one committed to CrewAI's native storage,
   one separately to the platform database, reconciled after the fact.

## Decision drivers

- Plan section 17.1 explicitly flags "competing persistence authorities"
  as a critical finding requiring correction.
- Resumability (masterplan section 19.3, plan M3.6) must be unambiguous
  about which checkpoint is authoritative after a crash.

## Selected option

`RunStateStore` (SQLite locally, PostgreSQL shared — ADR-003) is the one
authoritative checkpoint. If CrewAI Flow persistence is used at all, it is
implemented as an adapter that reads/writes through `RunStateStore`, not
as an independent second store.

## Rejected options and reason

- Option 2: requires an explicit transaction and reconciliation design
  that plan section 17.1 identifies as unaddressed risk; rejected until
  such a design exists and is justified by a concrete need.

## Security and compliance impact

None directly; reduces the risk of divergent/replayed state after a
crash, which could otherwise cause a run to silently repeat side effects.

## Operational impact

All Flow-step state reads/writes go through the `RunStateStore` port
(plan section 20.1); no direct CrewAI persistence API calls from
application code.

## Cost impact category

None.

## Portability impact

High (positive) — swapping the underlying database or even the
orchestration engine does not require touching Flow-step logic.

## Revisit trigger

None anticipated; revisit jointly with ADR-011 if the workflow substrate
changes.

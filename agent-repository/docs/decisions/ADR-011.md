# ADR-011: Workflow execution substrate

- **Decision owner:** project_architect
- **Decision date:** 2026-08-24
- **Status:** accepted
- **Scope:** Whether CrewAI Flow persistence alone is sufficient for the
  first production scope, or a durable workflow engine (e.g. Temporal) is
  required.

## Options considered

1. CrewAI Flow persistence backed by `RunStateStore` (SQLite/PostgreSQL)
   is sufficient for the first production scope (selected).
2. Adopt a dedicated durable-workflow engine (e.g. Temporal, LangGraph
   durable execution) underneath or alongside CrewAI Flow.

## Decision drivers

- Single-operator / small-team local-first deployment target (inception
  decision: local-only first).
- Avoid a second orchestration substrate before Flow persistence is proven
  insufficient (plan section 17.1).
- Minimize operational surface area for the MVP.

## Selected option

Use CrewAI Flow's state/persistence mechanism as the execution substrate,
with `RunStateStore` (ADR-012) as the single checkpoint authority backing
it. No separate durable-workflow engine is introduced for the MVP.

## Rejected options and reason

- Option 2: adds a new infrastructure dependency and operational
  complexity (deployment, monitoring, upgrade path) without a demonstrated
  need; revisit only if the exit criteria below are met.

## Security and compliance impact

None directly.

## Operational impact

Requires a compatibility regression suite before any CrewAI upgrade
(masterplan section 28 item 14) since Flow persistence behavior is
version-sensitive.

## Cost impact category

Low — no new infrastructure.

## Portability impact

Medium — CrewAI Flow persistence is wrapped behind `RunStateStore` so a
future migration to a durable-workflow engine only requires a new adapter,
not a rewrite of application/domain code.

## Revisit trigger (exit criteria for migration)

- Cross-process durable state is needed at a scale where DB-backed
  checkpointing becomes a bottleneck, or
- Distributed step retries/timeouts are needed beyond what CrewAI's Flow
  model supports natively, or
- Multi-region/multi-cluster execution is required.

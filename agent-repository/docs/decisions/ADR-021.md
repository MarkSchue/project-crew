# ADR-021: Small-task execution modes

- **Decision owner:** project_architect
- **Decision date:** 2026-08-24
- **Status:** accepted
- **Scope:** Defining `atomic`, `delegated`, `crew`, and `workflow`
  execution-mode semantics so a small task does not require a heavyweight
  Crew.

## Options considered

1. Add `procedure.execution_mode` enum to the SPOC schema with four modes
   (`atomic`, `delegated`, `crew`, `workflow`), all sharing the same
   control envelope (compile, authorize, budget, execute, validate,
   evidence, finalize), where `atomic` must not instantiate a Crew when a
   direct task or deterministic tool suffices (selected, plan section
   19.3).
2. Always instantiate a full CrewAI Crew regardless of task size.

## Decision drivers

- Plan section 17.1 flags "small-task execution is not modeled" as a
  critical finding.
- Avoids unnecessary orchestration overhead (and cost) for trivial,
  single-agent or single-tool work.

## Selected option

Implement the four execution modes exactly as specified in plan section
19.3, added to the SPOC schema (`spoc.schema.json`
`procedure.execution_mode`, already present in the schema shipped in
Phase 1). The Crew/Task factory (M3.4) branches on this field rather than
always building a full Crew.

## Rejected options and reason

- Option 2: wastes orchestration overhead and cost on tasks that need
  only one agent or one deterministic tool call, and obscures the
  difference between simple and compound work in telemetry.

## Security and compliance impact

None directly; all modes still pass through the same control envelope
(authorization, budget, evidence), so no mode bypasses governance.

## Operational impact

Crew/Task factory and manifest compiler must both understand the
execution mode (plan section 19.3, M3.2, M3.4).

## Cost impact category

Positive — `atomic` mode reduces unnecessary token/orchestration cost for
small tasks.

## Portability impact

None additional.

## Revisit trigger

None anticipated.

## Supersedes / superseded by

None.

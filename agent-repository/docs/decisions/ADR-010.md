# ADR-010: Version all registries, schemas, prompts, workflows, and evaluations

- **Decision owner:** project_architect
- **Decision date:** 2026-08-24
- **Status:** accepted
- **Scope:** Versioning discipline across all governed platform artifacts.

## Options considered

1. Semantic versioning (`MAJOR.MINOR.PATCH`) for agents, skills, tools,
   models, workflows, and schemas, with deprecation/replacement metadata
   and every run manifest recording the exact resolved versions (selected,
   masterplan section 11.2, plan section 20.4).
2. Unversioned "latest wins" registry entries.
3. Versioning only for schemas, informal versioning elsewhere.

## Decision drivers

- Reproducibility requires knowing exactly which agent/prompt/tool/model
  version executed a given run (masterplan section 29 acceptance
  criteria: "traceable").
- Silent model or prompt changes are an identified risk (masterplan
  section 25: "Silent model changes -> Quality regression").
- Compatibility across the three repositories requires explicit version
  ranges (plan section 23.4).

## Selected option

Every registry entry, schema, prompt, and workflow definition carries a
semantic version; every compiled run manifest records the exact resolved
version and content hash of everything involved (plan section 20.4
execution fingerprint). Deprecation and replacement metadata is mandatory
before an entry can be marked `deprecated`.

## Rejected options and reason

- Option 2: makes runs non-reproducible and silently breaks callers when
  an entry changes underneath them.
- Option 3: leaves agents/prompts/tools/models exactly where the
  "silent model changes" risk materializes; versioning must be uniform to
  close that gap.

## Security and compliance impact

Enables precise rollback and impact analysis when a vulnerability or
regression is traced to a specific version.

## Operational impact

Requires CI compatibility checks (plan section 23.4) whenever a version
changes across the three repositories.

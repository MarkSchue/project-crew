# ADR-019: Multi-repository release compatibility

- **Decision owner:** project_architect
- **Decision date:** 2026-08-24
- **Status:** accepted
- **Scope:** Version ranges, compatibility matrix, release train, and
  integration-test process across `agent-repository`,
  `project-template-repository`, and `active-project-repo`.

## Options considered

1. Each release publishes a compatibility manifest (plan section 23.4
   exact schema: `platform_version`, `agent_repository`,
   `supported_template_versions`, `supported_project_schema`,
   `supported_spoc_schema`, `supported_workflow_contracts`); a dedicated
   integration fixture pins all three repositories and runs the vertical
   slice; compatibility CI must pass before merge (selected).
2. No formal compatibility tracking; assume latest-with-latest always
   works.
3. Lockstep versioning: all three repositories always share one version
   number.

## Decision drivers

- Plan section 17.1 flags "three independent repositories need release
  coordination" as a high finding.
- Repositories evolve at different cadences (agent code vs. governance
  templates vs. one active project).

## Selected option

Publish the compatibility manifest from plan section 23.4 on every
`agent-repository` release; maintain an integration-test fixture pinning
specific versions of all three repositories and running the masterplan
section 27 vertical slice against them in CI.

## Rejected options and reason

- Option 2: silently breaks projects when template or schema versions
  drift, directly causing the risk plan section 17.1 identifies.
- Option 3 (lockstep): forces unrelated repositories to release together
  even when only one changed, adding unnecessary coordination overhead.

## Security and compliance impact

None directly; reduces the risk of running an active project against an
incompatible template/schema version.

## Operational impact

Requires a CI job dedicated to the cross-repository integration fixture,
separate from each repository's own unit/contract test suite.

## Cost impact category

Low — CI time only.

## Portability impact

None additional.

## Revisit trigger

None anticipated.

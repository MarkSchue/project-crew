# ADR-013: Event authority and evidence projection

- **Decision owner:** project_architect
- **Decision date:** 2026-08-24
- **Status:** accepted
- **Scope:** Whether the database event ledger or the `events.jsonl` file
  is authoritative, and how atomic publication/reconciliation works.

## Options considered

1. Database event ledger (within the same transaction as the business
   state change) is authoritative; a transactional outbox publishes to
   SSE/stream consumers; a run-evidence projector appends the canonical
   redacted representation to `events.jsonl` (selected, plan section
   22.1).
2. `events.jsonl` is authoritative; the database is a secondary read
   model built by tailing the file.
3. Dual-write both, without a defined reconciliation process.

## Decision drivers

- Plan section 17.1 flags "JSONL and database events can diverge without
  an outbox or reconciliation rule" as a high finding.
- Need transactional atomicity between business state change and event
  record (plan section 22.1 step 1).
- `events.jsonl` must remain a portable, human/agent-readable run-evidence
  artifact (masterplan section 16).

## Selected option

The database is authoritative via the outbox pattern (plan section 22.1
steps 1-5): business state change and event record commit in one DB
transaction; a transactional outbox publishes the event; a projector
appends the redacted, canonical event to `events.jsonl` on the run
branch/artifact store; a reconciler detects unpublished/unprojected
events; finalization hashes the ordered event stream into the run
summary.

## Rejected options and reason

- Option 2: file-tailing as the primary consistency mechanism is harder to
  make transactional and query-efficient than a database ledger.
- Option 3: explicitly rejected by plan section 22.1 ("the implementation
  may not casually dual-write").

## Security and compliance impact

Enables the three-tier redaction model (operational / audit / debug,
plan section 22.3) applied consistently at the projection step.

## Operational impact

Requires a reconciler process/job (plan section 22.1 step 4) to detect and
resolve unpublished or unprojected events.

## Cost impact category

Low — no new infrastructure beyond the already-selected operational
database.

## Portability impact

Medium — `EventLedger` is an application port (plan section 20.1);
`events.jsonl` remains a portable evidence artifact independent of the
database technology.

## Revisit trigger

None anticipated.

# ADR-005: Use deterministic capability matching with governed semantic inference

- **Decision owner:** project_architect
- **Decision date:** 2026-08-24
- **Status:** accepted
- **Scope:** How SPOCs are matched to agents (Phase 2 matcher).

## Options considered

1. Four-stage deterministic matcher (validate explicit capabilities, expand
   aliases/dependencies, optionally LLM-extract candidate capabilities from
   procedure text, apply deterministic scoring/filters/policy) with any
   LLM-derived capability marked `inferred` and gated by risk-based
   approval (selected, masterplan section 3.3, 12.2, 12.3).
2. Pure LLM-based agent selection from a natural-language task
   description.
3. Static, hand-wired routing table (SPOC type -> agent).

## Decision drivers

- Matching decisions must be reproducible and explainable (masterplan
  section 29 acceptance criteria).
- Capability inflation (an agent silently gaining scope) is an identified
  risk (masterplan section 25).
- The system must scale beyond a fixed number of hand-wired routes as
  agents and SPOC types grow.

## Selected option

Deterministic scoring and hard filters decide agent selection for explicit
capabilities; an LLM may only propose additional candidate capabilities
from procedure text, which are marked `inferred` and require human
approval above a configurable risk threshold before they can expand agent
selection (masterplan section 12.3).

## Rejected options and reason

- Option 2: non-reproducible, unexplainable selection; fails the
  auditability requirement (masterplan principle 12).
- Option 3: does not scale and reintroduces the same rigidity the
  three-repository/agent-registry model was designed to avoid.

## Security and compliance impact

Explicit tie-break rule (lowest `agent_id` lexicographically) removes
selection randomness; inferred high-risk capabilities cannot silently
expand agent selection without approval.

## Operational impact

Requires a capability registry with evidence-backed proficiency levels
(masterplan section 11.2) before the matcher can run meaningfully.

## Cost impact category

None additional; inference step uses the same model budget as any other
LLM call within the SPOC's cost ceiling.

## Portability impact

None additional.

## Revisit trigger

None anticipated for the MVP; revisit if capability taxonomy outgrows a
flat catalog (e.g. needs versioned capability schemas).

## Supersedes / superseded by

None.

## Related milestones and tests

- Plan milestones M2.1-M2.5 (registry, matcher, explainer, scaffolding).

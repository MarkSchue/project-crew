# ADR-001: Use CrewAI Flows for orchestration and Crews for bounded collaboration

- **Decision owner:** project_architect
- **Decision date:** 2026-08-24
- **Status:** accepted
- **Scope:** Runtime orchestration model for all SPOC execution.

## Options considered

1. CrewAI Flows for durable orchestration, Crews for bounded collaborative
   work inside flow steps (selected).
2. A generic custom state machine with CrewAI Agents called ad hoc.
3. A separate durable-workflow engine (e.g. Temporal) driving CrewAI
   Agents directly, with no Flow layer.

## Decision drivers

- Need explicit, inspectable state transitions per SPOC (masterplan
  section 13.1).
- Need to keep collaborative multi-agent work bounded and time-limited
  rather than open-ended.
- Want to reuse CrewAI's built-in state/structured-output/guardrail
  support instead of re-implementing it.

## Selected option

Use CrewAI `Flow` as the durable orchestration boundary for one SPOC's
execution lifecycle, with each lifecycle step (compile, authorize,
execute, validate, accept, finalize) implemented as an explicit Flow
method/state transition (masterplan section 13.1, plan section 8 M3.3).
Use bounded `Crew`/`Task` objects only inside the `execute_bounded_crews`
step for collaborative work that genuinely needs multiple agents; a
single-agent, single-tool step uses the `atomic` execution mode instead of
instantiating a Crew (plan section 19.3).

## Rejected options and reason

- Option 2 (custom state machine): would duplicate functionality CrewAI
  already provides and increase framework-coupling risk without a
  compensating benefit.
- Option 3 (Temporal-first): adds a second orchestration substrate before
  CrewAI Flow persistence has been shown insufficient; revisited under
  ADR-011.

## Security and compliance impact

None directly; the Flow enforces step ordering, which is a precondition
for the approval and policy gates in later steps.

## Operational impact

CrewAI version is pinned and recorded in every run manifest (plan section
20.4); a compatibility regression suite runs before any CrewAI upgrade
(masterplan section 28 item 14).

## Cost impact category

Low — no additional infrastructure; cost is bounded by SPOC-level budget
limits (masterplan section 10.2 `constraints`).

## Portability impact

Medium — Flow/Crew logic is wrapped behind application ports (plan
section 20.1) so project artifacts remain usable without CrewAI
(masterplan principle 13).

## Revisit trigger

CrewAI Flow persistence proves insufficient for durable checkpointing at
production scale, or CrewAI's execution model changes incompatibly
(tracked jointly with ADR-011).

## Supersedes / superseded by

None.

# ADR-002: Use Git and OKF Markdown as authoritative project records

- **Decision owner:** project_architect
- **Decision date:** 2026-08-24
- **Status:** accepted
- **Scope:** System of record for all project knowledge and decisions.

## Options considered

1. Git-versioned OKF Markdown files as the sole system of record for
   project knowledge, with an operational database for runtime state only
   (selected).
2. A database-first system of record with Markdown as a generated export.
3. A proprietary document store / wiki as the system of record.

## Decision drivers

- Teams must be able to work in VS Code and Git without a proprietary UI
  (masterplan section 2.2).
- Project knowledge must be navigable as a graph and diffable/reviewable
  like code.
- Runtime concurrency needs (locking, leases) are a poor fit for plain
  files (masterplan section 3.2).

## Selected option

Git and OKF Markdown are authoritative for project facts, decisions, and
deliverables. SQLite (local) / PostgreSQL (shared) are operational state
stores for queues, leases, run state, and indexes — not a second system of
record (masterplan section 3.2, plan section 19.5).

## Rejected options and reason

- Option 2: would make Markdown a lossy projection, breaking the
  "artifacts remain usable without CrewAI/without the platform" principle.
- Option 3: reintroduces a proprietary UI dependency the project
  explicitly avoids (masterplan section 2.2).

## Security and compliance impact

Classification labels and access rules apply per-file (`public`/
`internal`/`confidential`/`restricted`); Git history itself does not
replace execution telemetry (masterplan principle 7).

## Operational impact

Requires branch-per-run Git operating model (ADR-006) and generated,
non-hand-edited indexes (masterplan section 9.4).

## Cost impact category

Low — Git hosting only; no additional document-store infrastructure.

## Portability impact

High (positive) — project data is fully portable Markdown/YAML/JSON,
independent of any specific platform vendor.

## Revisit trigger

Concurrency or query requirements exceed what an operational database
projection can support without compromising Git as the record of truth.
